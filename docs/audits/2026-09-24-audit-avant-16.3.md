# Audit de consolidation — avant l'étape 16.3

Date : 2026-09-24 · Branche : `develop` · HEAD : `f0f1eb1` (+ arbre de travail modifié) · origin/develop : `394597c`

Instantané daté : ce document n'est pas maintenu. L'état vivant est dans [`../progress.md`](../progress.md).

> **Suite** : les corrections P0 à P3 ont été appliquées le même jour (sauf celles rattachées à 16.3 et la licence). Détail des résolutions : `progress.md` §5. Les constats C/I/A/O de ce rapport y sont suivis sous des identifiants KI.

## Méthode et limites

- Lecture de tout le code backend et frontend, de la configuration, des migrations, des tests, de `docs/`, `docs/steps/` (01 → 16.3) et `docs/prompts/`, de l'historique Git.
- **Frontend vérifié** : `npm ci`, `ng test`, `ng build` sous Node 24.21.
- **Backend non vérifié par exécution** : Maven Central était inaccessible depuis l'environnement d'audit (politique réseau). Aucune affirmation « compile » ou « tests verts » n'est faite pour le backend ; les constats backend viennent de la lecture du code et de l'historique Git.

## A. État général

Le socle est de bonne qualité pour un projet à ce stade : périmètre explicite, modèle métier avec invariants, monolithe modulaire protégé par ArchUnit, Flyway propriétaire du schéma, tests d'intégration sur PostgreSQL réel, erreurs RFC 9457, hooks de commit.

Deux problèmes empêchent de reprendre proprement 16.3 :

1. **16.2 n'est pas réellement terminée dans Git** : une partie du code est restée dans l'arbre de travail et le HEAD ne compile pas.
2. **L'architecture réelle du backend diverge de toute la documentation et des fiches d'étape** : le module `profile` suit une structure ports/adaptateurs non documentée, alors que les fiches (y compris 16.3) prescrivent une structure en couches simples.

Le reste relève de corrections ciblées (bouchons dans un adaptateur, perte de champs dans un mapper, tests mal nommés, configuration par défaut en `dev`) et de documentation obsolète, corrigée pendant cet audit.

## C. Problèmes détectés

Classement : **CRITIQUE** (bloque la reprise) · **IMPORTANT** (défaut réel à corriger bientôt) · **AMÉLIORATION** · **OPTIONNEL**. Type : *réel*, *recommandation*, *style*.

### CRITIQUE

**C1 — 16.2 partiellement commitée, HEAD ne compile pas** · réel
- Zone : Git, `ProfileEntity.java`, `SkillEntity.java`, `PublicProfileControllerTest.java`
- Constat : `c700268` contient les tests de 16.2 sans le code ; `f0f1eb1` (même message) ajoute les entités et `V003`, mais les collections et `addExperience/addEducation/addCertification` de `ProfileEntity` sont restés non commités. `ProfileMappingIT` (commité) appelle `profile.addExperience(...)`. Les deux commits ne sont pas poussés.
- Impact : aucun des deux commits ne compile ; `git bisect` et la CI future seraient cassés ; un clone du dépôt est inutilisable.
- Recommandation : fusionner `c700268` + `f0f1eb1` + les 3 fichiers modifiés en **un** commit (`git reset --soft 394597c`, puis `git add` ciblé et commit), lancer `./mvnw verify`, pousser.
- Justification : les commits ne sont pas poussés, la réécriture est donc sans risque ; un commit par sous-étape qui compile seul est la convention du projet.

**C2 — Architecture réelle ≠ architecture documentée et fiches d'étape** · réel
- Zone : `backend/.../profile/**`, `docs/04-architecture-backend.md` §6, `docs/05-conventions-api.md` §23/§32, toutes les fiches 14.x–16.3
- Constat : code en `domain/model`, `domain/port`, `application/usecase`, `infrastructure/persistence/jpa/{entity,mapper,repository}`, `web/{controller,dto}` ; documentation et fiches en `api/`, `domain/` (entités JPA), `repository/`, `service/`. La fiche 16.3 demande de modifier `profile/repository/ProfileRepository.java` et `profile/service/ProfileQueryService.java`, qui n'existent pas.
- Impact : chaque étape future doit être traduite à la main ; risque de mélange des deux styles (déjà visible : `DateRange` dans l'infrastructure mais testé dans `profile.domain`).
- Recommandation : valider l'[ADR 0001](../decisions/0001-architecture-interne-des-modules.md) (garder ports/adaptateurs légers, avec garde-fous) — docs 04/05 déjà alignés sur ce choix.
- Justification : coût de migration nul pour l'existant, domaine testable sans infrastructure, contrat HTTP découplé de JPA ; la cérémonie est contenue par des règles explicites (pas de port entrant, pas de méthode bouchon).

### IMPORTANT

**I1 — Bouchons silencieux dans `ProfileRepositoryAdapter`** · réel
- `findById` renvoie toujours `Optional.empty()`, `exists` toujours `false`, `delete` ne fait rien.
- Impact : un futur appelant obtient une réponse fausse sans erreur.
- Recommandation : retirer ces trois méthodes du port `ProfileRepository` (aucun appelant) ; les réintroduire avec le cas d'usage qui en aura besoin (étape 36).

**I2 — `ProfilePersistenceMapper.toEntity` perd des champs** · réel
- `aboutMarkdown`, `publicLocation`, `publicEmail` ne sont pas copiés ; `Profile.create(...)` force aussi `aboutMarkdown` et `publicLocation` à `null`.
- Impact : `save(profile)` écrase silencieusement ces valeurs (aujourd'hui seulement via le seeder, demain via l'admin).
- Recommandation : copier tous les champs ; ajouter un test aller-retour du mapper. Renommer `ProfileSeeder.seedAdmin()` en `seedProfile()`.

**I3 — Tests d'intégration nommés `*Test`** · réel
- `ActuatorHealthTest` et `GetProfileUseCaseTest` héritent d'`AbstractIntegrationTest` (Docker) mais sont exécutés par Surefire.
- Impact : `./mvnw test` exige Docker, contrairement à `06-strategie-tests.md` §2.1/§20.
- Recommandation : renommer en `ActuatorHealthIT`, `GetProfileUseCaseIT` ; retirer l'`@AutoConfigureMockMvc` redondant et les imports inutilisés.

**I4 — Profil `dev` actif par défaut** · réel
- `application.yaml` : `spring.profiles.active: dev`.
- Impact : tout lancement sans variable explicite (y compris une future image Docker) active le seeder et `show-details: always`.
- Recommandation : retirer la ligne ; activer `dev` par la configuration d'exécution de l'IDE ou `-Dspring-boot.run.profiles=dev` (déjà prévu dans la fiche 08).

**I5 — `open-in-view` désactivé seulement en test** · réel
- Impact : en `dev`, un chargement paresseux accidentel dans un contrôleur fonctionnerait, alors qu'il échouerait en test : comportements divergents.
- Recommandation : `spring.jpa.open-in-view: false` dans `application.yaml`.

**I6 — Import de `deploy/.env` dépendant du répertoire de travail** · réel
- `application-dev.yaml` : `optional:file:./deploy/.env[.properties]` ; la fiche 08 fait lancer depuis `backend/` (où ce chemin n'existe pas). L'import étant `optional`, l'échec est silencieux et se manifeste par une erreur de connexion.
- Recommandation : `import: optional:file:./deploy/.env[.properties],optional:file:../deploy/.env[.properties]`.

**I7 — Aucun test HTTP de bout en bout** · réel
- `PublicProfileIT` (prévu en 14.4) est absent. `GetProfileUseCaseTest` est `@Transactional` : il ne peut pas prouver ce qui est chargé hors transaction, et aucun test ne compte les requêtes (argument central de D-O en 16.3).
- Recommandation : créer `PublicProfileIT` (MockMvc + base) ; en 16.3, vérifier le nombre de `SELECT` via les statistiques Hibernate.

**I8 — Invariants métier dans les entités JPA** · réel (conséquence de C2)
- `DateRange` est dans `infrastructure.persistence.jpa.entity` ; la garde de `Certification` est dans `CertificationEntity` ; le domaine n'a pas encore `Experience`/`Education`/`Certification`. `DateRangeTest` et `ProfileTest` sont rangés dans `profile.domain` mais testent l'infrastructure ; `ProfileTest` teste en réalité `CertificationEntity`.
- Recommandation (en 16.3) : créer les records domaine `Experience`, `Education`, `Certification`, `DateRange` dans `profile.domain.model` avec leurs gardes ; les entités JPA gardent leurs colonnes ; déplacer les tests unitaires avec les classes.

**I9 — API des entités incohérente et contournable** · réel
- `addLink(label, url, order)` fixe la référence arrière ; `addExperience(entity)` ne la fixe pas (l'appelant doit penser à `.profile(profile)`). `@Builder` + `@AllArgsConstructor` + `@Setter` permettent de construire un `ProfileEntity` sans `id = 1`, ou de contourner la garde de `CertificationEntity` par un setter.
- Recommandation : `@NoArgsConstructor(access = PROTECTED)`, pas de `@AllArgsConstructor`/`@Setter` publics sur les entités ; méthodes `addX(...)` qui positionnent `x.profile = this`.

**I10 — Contrat public incohérent avec C03 et D-P** · réel
- `SkillResponse` expose `id` et `displayOrder` (plus un champ commenté) ; `ProfessionalLinkResponse` expose `displayOrder`. La fiche 16.3 (D-P) dit : ni `id` ni `displayOrder` publics, l'ordre du tableau suffit.
- Recommandation : trancher en 16.3 pour tout le profil (aucun client frontend n'existe encore : la rupture est gratuite maintenant, coûteuse plus tard).

**I11 — Pas de CI** · réel
- `.github/` absent ; la CI est prévue seulement en 52.12 alors que le dépôt est poussé depuis l'étape 03.
- Recommandation : workflow minimal maintenant (JDK 25 + `./mvnw verify` ; Node 24 + `npm ci`, `npm test -- --watch=false`, `npm run build`). Docker est disponible sur les runners Ubuntu de GitHub pour Testcontainers.

**I12 — `docs/steps/` et `docs/prompts/` ignorés par Git** · décision à prendre
- Impact : les fiches d'étape et le prompt de continuité ne sont pas versionnés ; perte déjà constatée (`ÉTAPE 15.1` vide, décisions D-D à D-G perdues).
- Options : (a) les versionner (historique complet, mais contenu pédagogique généré rendu public) ; (b) les garder privés mais sauvegardés ailleurs (projet claude.ai, autre dépôt privé). Dans les deux cas, toute décision est désormais reportée dans `docs/decisions/` (versionné).

**I13 — Documentation obsolète ou erronée** · réel — **corrigé pendant l'audit** (voir §I)
- `04` : classe `PortfolioApplication` (réelle : `Application`), structure interne des modules ; `05` §23/§32 : paquets `..api..`/`..domain..` ; `02` : `ProfileResponse` à la place de `Profile` (effet d'un renommage IDE au commit `9633987`) ; `03` : fichier tronqué au §10 ; `01` D23 : formulation contradictoire ; `conventions-git` §21 : bloc dupliqué contradictoire (`test` vs `verify`) ; `06` et fiches : `compose.dev.yaml` alors que le fichier s'appelait `compose.dev.yml` ; README : `psql` local présenté comme prérequis alors que `03` §2.4 dit le contraire.

**I14 — Test frontend rouge** · réel — **corrigé pendant l'audit**
